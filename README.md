# 草野球スコア

草野球のスコア入力と成績集計を行う PWA（ホーム画面に追加して使う Web アプリ）。
サーバもアカウントも不要で、データは端末の中だけに保存される。

## 特徴

- **走者（ランナー）を管理**：誰がどの塁にいるかを常時表示し、得点・打点・盗塁を自動計算
- **走者がいなければ2タップ**で入力（結果 → 打球方向）。走者がいる時だけ進塁パネルが出る
- **全員打ち対応**：打順は9人固定ではなく可変長（途中参加・途中離脱も記録可）
- **相手の打順は試合中に増やせる**（メンバー表を交換しない草野球の実態に合わせた運用）
- **両チームの攻撃を記録**し、守備位置から自チームの失策を自動集計
- 球数の記録は3モードから選択（記録しない / 球数のみ / 最終カウント）
- 試合・年度別・**生涯通算**の成績を自動集計（打撃・投手・守備）
- **投手成績**：イニング途中の交代にも対応し、投球回・防御率・WHIP まで自動算出
- **守備（失策）集計**：種類別（捕球／送球）と守備位置別の内訳つき
- アプリ導入以前の年度別成績（**打撃・投手とも**）を手入力して通算に合算できる
- 成績表を**単体 HTML ファイル**で書き出し（LINE で送れば誰でも閲覧可）
- オフラインで動作（球場の電波が悪くても使える）

## 2つの入力モード

画面下の「試合」タブの一番上、または設定タブで切り替える。

| モード | 用途 |
|---|---|
| **試合のスコア** | チームの試合を丸ごと記録する（走者・投手・失策まで） |
| **個人成績** | スコアを付けずに、選んだメンバー1人の成績だけを残す |

### 個人成績モード

チームでスコアを付けられなかった試合や、各自が自分の記録だけ管理したい場合に使う。
メンバー一覧から対象の選手を選び、試合ごとに記録を足していく。入力方式は2通り。

| 方式 | 内容 |
|---|---|
| **打席ごとに入力** | 結果 → 打球方向（任意）→ 打点 → 確定 |
| **合計を直接入力** | 「4打数2安打」のように1試合の合計をまとめて書く |

打席ごとの入力では、打球方向をタップしても確定にはならない。
方向を選び、打点を入れてから「確定」を押す（安打でも打点を入れられるようにするため）。

集計される項目：試合数・打席・打数・安打・二塁打・三塁打・本塁打・塁打・打点・得点・
四球・死球・三振・犠打・犠飛・併殺・盗塁・盗塁死・失策と、打率・出塁率・長打率・OPS。

- 得点・盗塁・失策は打席結果から出せないため、別途まとめて入力する
- **投手成績**は結果だけの簡易入力（投球回・被安打・奪三振・与四死球・失点・自責点・勝敗）
- 年度別と通算がその場で集計される

チームのスコアで記録した試合と個人記録は**自動で合算**される（設定でオフにできる）。
同じ試合が両方にある場合は、日付と対戦相手で照合してチーム側だけを数える。
ダブルヘッダーなど別の試合を誤判定したときは、個人記録の画面で「数える」に切り替える。
これにより、個人成績画面と成績タブで同じ選手の通算は必ず一致する。

### 1試合の結果表

試合詳細に、打者ごとに各回の打席結果（左安・二ゴロ・中飛など）を並べた結果表を表示する。
「試合結果を書き出す（HTML）」で単体ファイルにでき、LINE で配れる。
列が多いので表は横スクロールさせ、選手名の列は固定している（スマホでも同じ表）。

## 走者まわりの考え方

塁上の状態を持たないと、打点・得点・フォースアウトを正しく記録できないため、
走者を「誰がどの塁にいるか」で常時保持している。

**進塁は結果から自動で埋まる。** 例えば四球なら詰まっている走者だけが進み、
犠飛なら三塁走者が生還し、併殺打なら打者と先頭の封殺走者がアウトになる。
実際と違った時だけ、進塁パネルで行き先を押し直せばよい。

| 場面 | 操作 |
|---|---|
| 走者なし | 結果 → 打球方向（従来どおり2タップ） |
| 走者あり | 結果 → 打球方向 →（必要なら進塁を直す）→ 確定 |
| 併殺・フォースアウト | 進塁パネルで対象の走者を「アウト」にし、アウトになった塁を選ぶ |
| 離塁アウト（飛び出して帰塁できず） | 走者を「アウト」にして、アウトの塁で「◯塁(帰塁)」を選ぶ |
| 打者は生きて走者がアウト | 「野選」を選ぶと既定でこの形になる |
| 失策で走者が進んだ | 進塁パネルで行き先を指定（失策による得点は打点が付かない） |
| 盗塁・重盗・ホームスチール | 「走塁」→ 盗塁 → **塁上の全走者**の行き先を指定 |
| 暴投・捕逸・牽制悪送球・タッチアップ | 「走塁」→ 原因を選ぶ → 全走者の行き先を指定 |
| 打者が失策で余分に進塁 | 打席の「＋ 詳細を入力」で打者の行き先を指定 |
| 失策が重なった | 失策セクションで守備位置と種類（捕球／送球）を何個でも追加 |
| 記録がずれた | 塁の表示をタップして走者を消す・入れ替える |

走者がいないと成立しない結果（併殺打・犠打・野選）と、三塁走者がいないと成立しない犠飛は、
その場面では薄く表示され、押しても理由が出るだけで記録されない。2アウトでも同様。

### 失策の記録

失策は打席結果とは独立して記録する。「安打だが送球エラーで二塁まで進んだ」
「ゴロを弾いたうえに一塁へ悪送球した」のように、**1つのプレーで何個でも**追加できる。

- 守備位置と種類（捕球／送球／その他）を選ぶ
- 自チームが守っている時だけ、その回の守備配置から選手を割り出して失策数に加算する
- 走塁中の失策（牽制悪送球など）も同じ形で記録できる
- **暴投・捕逸は記録上の失策ではない**ので、原因として選んでも失策は加算されない

打者が失策などで余分に進塁した場合は、打球方向の下にある
「＋ 詳細を入力（打者の進塁・失策）」を開くと打者の行き先を指定できる。
開かずに打球方向をタップすれば、これまでどおり即確定する。

### 守備位置・DH・控え

打順の各選手には、9つの守備位置のほかに **DH**（打つが守備につかない）と
**控え**（ベンチ）を割り当てられる。全員打ちなので、守備位置を割り当てていない選手は
既定で DH 扱いになる。打順の行の右端に出るタグがその区分。

### 相手チームの打順

草野球では試合前にメンバー表を交換しないため、**打席が進むたびに相手打者が自動で増えていく**。
相手の攻撃が一巡して1番に戻ったら、打席入力画面か「打順・守備」画面の
**「打順を確定（N人）」** を押す。確定すると以降は登録済みの人数で巡回し、次打者は1番に戻る。

N は「実際に打席に立った人数」。打順は次の打者を先回りして用意するため、
確定を押す時点では打っていない打者が1人多く並んでいるが、
名前を登録していないものは確定時に自動で取り除かれる。

- 確定前でも「打者を変更」から任意の番号を選んだり、新しい番号を足したりできる
- 相手打者にも名前・背番号を登録できる（分かった時点で入れればよい）
- 自チームと同じく**途中参加・途中離脱**を設定でき、離脱した打者は打順から飛ばされる
- 人数が変わったら「確定を解除」して直せる

### 投手成績

相手の攻撃中に記録した内容から自動集計する。**イニング途中の投手交代**にも対応しており、
打席入力画面の「投手交代」を押した時点以降が新しい投手の記録になる。

| 項目 | 出し方 |
|---|---|
| 投球回 | 記録したアウト数から 1/3 単位で算出 |
| 被安打・被本塁打・奪三振・与四死球 | 打席結果から自動 |
| 失点 | その投手が投げている間に本塁に到達した走者の数 |
| 自責点 | 既定は失点と同じ。試合詳細の投手成績をタップして手で直す |
| 勝敗・セーブ | 同じ画面で手入力 |
| 防御率 | 自責点 ÷ 投球回 × 基準イニング（既定9回、設定で7回に変更可） |
| WHIP | (被安打＋与四球＋与死球) ÷ 投球回 |

自責点を手入力にしているのは、失策がからんだ得点を自責点から除く判断が
規則上スコアラーに委ねられており、自動判定が実用的でないため。

### 守備（失策）集計

自チームが守っている間の失策だけを数える。打席中・走塁中の両方が対象。
選手ごとに **種類別（捕球／送球／その他）** と **守備位置別** の内訳が出る。

### 記録の修正

**一番新しい記録**の結果を変えると、いったん取り消して入れ直す扱いになる。
3アウト目を安打に直せば、攻守交代が取り消されて同じ回の2アウトに戻り、打順も戻る。
入れ直しを途中でやめた場合は元の記録がそのまま残る。

それより前の記録を変えた場合は成績だけが直り、イニングや塁の状況は動かない
（後続のプレーを壊さないため）。ずれた場合は走者の表示をタップして直す。

得点は走者が本塁に到達した時点で自動計上され、得点者も記録される。
打点は自動算出（失策・併殺打・野選による得点は0）で、必要なら手で直せる。

走塁は1回の操作で**複数の走者を同時に動かせる**。三塁走者のホームスチールに
一塁走者が便乗した、といった場面でも1つの記録として残せる。
さらに走者ごとに記録区分を選べるので、
「三塁走者は盗塁、便乗した一塁走者は進塁（盗塁は付けない）」といった区別ができる。

| 記録区分 | 成績への反映 |
|---|---|
| 盗塁 | 盗塁数に加算 |
| 進塁 | 加算しない（塁だけ動く） |
| 盗塁死 | 盗塁死に加算＋アウト |
| 走塁死 | 加算しない＋アウト |

## 「ホーム画面に追加」は何をしているのか

App Store のアプリのような**インストールではない**。実体は Safari(WebKit) が動かす
Web アプリで、iPhone の設定 →「iPhone ストレージ」にもアプリとしては現れない。

ただし単なるショートカットでもない。追加した時点で、
**アプリのファイル一式が端末内（Cache Storage）に保存される**ため、
2回目以降は通信せずに起動し、圏外でも動く。

| | App Store のアプリ | このアプリ |
|---|---|---|
| 実体 | アプリ本体を端末にインストール | Web アプリ＋端末内キャッシュ |
| iPhone ストレージに表示 | される | されない（Safari のデータ扱い） |
| 起動時の通信 | 不要 | **不要**（実測 0 バイト） |
| 圏外での動作 | 可 | **可** |
| 削除したとき | アプリが消える | アイコンと**データも消える** |

最後の行が重要で、アイコンを削除すると成績データも一緒に消える。
機種変更でも引き継がれない。だからバックアップの書き出しが必要になる。

## 通信量について

ホーム画面に追加した時点で、アプリのファイル一式（約150KB）が端末内に保存される。
**以降の起動では通信が一切発生しない**（実測 0 バイト）。

| 場面 | 通信量 |
|---|---|
| 初回インストール | 約150KB（1回だけ） |
| 2回目以降の起動 | **0バイト** |
| 試合のスコア入力 | 0バイト（データは端末内のみ） |
| 更新の取得 | 約150KB（設定画面で手動実行したときだけ） |

Service Worker は cache-only。キャッシュにあるものは通信せずに返す。
更新を自動で取りに行かないので、更新したいときは設定画面の「更新を確認」を押す
（Wi-Fi のときに実行する想定）。

## 使いはじめる順番

1. **メンバー**タブで選手を登録（過去の年間成績があればここで取り込む）
2. **試合**タブ →「＋ 新規」で試合を作成
3. 打順にその日の参加者を全員追加 → グラウンド図で守備位置を割り当て
4. 「打席入力へ」で記録開始
5. 試合後、**設定**タブから「書き出す」でバックアップ

## バックアップについて（重要）

iOS はブラウザのデータ保持を保証しない。**アプリを消す・機種変更する・ブラウザにデータを削除される**と
通算成績まで失われる。次のいずれかを習慣にすること。

- 試合ごと：試合詳細の「この試合を書き出す」
- まとめて：設定タブの「書き出す」

書き出し時に共有シートが出るので、**「"ファイル"に保存」で iCloud Drive** に置くのが確実。
最後のバックアップから既定で7日経つと、画面上部に警告バナーが出る。

## 当番制でスコアを付ける場合

クラウド同期は使っていないが、試合データは1試合ごとに独立しているため競合しない。

1. 当番の人が自分のスマホで同じ URL を開いて入力
2. 試合詳細の「この試合を書き出す」でファイルを作り、LINE などで送る
3. 本体端末の 設定 →「取り込む」で読み込む

書き出したファイルには**その試合に出ている選手も同梱**される。取り込み側では
同じ名前の選手に自動で結び付けられるので、選手が二重に増えることはない。

## 開発メモ

ビルドツールなし。素の ES モジュールで動く。

```
index.html          画面の骨格
manifest.webmanifest
sw.js               オフライン用 Service Worker
css/style.css
js/
  app.js            起動処理
  db.js             IndexedDB ラッパ
  model.js          打席結果・守備位置などの定義
  store.js          データアクセスと試合進行のロジック
  stats.js          成績集計（手入力の過去成績も合算）
  runners.js        走者の管理と進塁計算
tools/devserver.py  開発用サーバ（キャッシュ無効）
  backup.js         書き出し・取り込み
  report.js         単体 HTML 成績表の生成
  ui/               画面（router / games / lineup / score / players / stats / settings / personal）
tools/make_icons.py アイコン生成（Pillow）
```

ローカルで動かす場合：

```bash
python C:/Users/tmats/baseball-score/tools/devserver.py 8765
```

`http://127.0.0.1:8765/` を開く。

> 既知の制限：ローカルの `http://127.0.0.1` では Service Worker の登録に失敗する
> ことがある（ブラウザ側の制約）。オフライン動作の確認は公開URLで行うこと。
>
> **開発中は `http://127.0.0.1:8765/index.html?nosw=1` を使うこと。**
> Service Worker はキャッシュ優先で動くため、コードを変更しても反映されない。
> `?nosw=1` を付けると Service Worker を解除してキャッシュも消し、常に最新を読む。
> `devserver.py` は `Cache-Control: no-store` を付けて配信するので、
> ブラウザ側のキャッシュにも引っかからない（標準の `http.server` だとこれが起きる）。
